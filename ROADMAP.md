# Greenline: roadmap

**Greenline** — лёгкий веб-чат поверх GREEN-API. Название отсылает к GREEN-API и к «линии связи».

Срок по ТЗ: 5 дней. План рассчитан на 3 рабочих дня и оставляет запас.

## Критерии готовности (из ТЗ)

1. Пользователь открывает сайт и вводит `idInstance` и `apiTokenInstance` (плюс `apiUrl` из консоли GREEN-API).
2. Вводит номер получателя и создаёт новый чат.
3. Пишет текст и отправляет его методом `SendMessage`.
4. Получатель отвечает в мессенджере.
5. Ответ появляется в чате. Получение идёт через HTTP API: `ReceiveNotification` + `DeleteNotification`.
6. Только текстовые сообщения, минимум функций, внешний вид по мотивам web.max.ru, React.

## Фазы

### Фаза 0 — фундамент (Architect) ✅

- [x] Каркас Vite + React + TS + Vitest + zustand
- [x] Доменные типы `src/types.ts`
- [x] Контракты-заглушки: `GreenApiClient`, `phone.ts`, `ChatState`, `useNotificationPolling`
- [x] CLAUDE.md, ROADMAP.md, задачи ролей
- [x] Первый коммит в `main`

### Фаза 1 — параллельная разработка (роли 1–4 одновременно) ✅

- **API**: HTTP-клиент GREEN-API, парсинг вебхуков, нормализация номера, тесты на замоканном `fetch`.
- **UI**: презентационные компоненты в стиле MAX (экран входа, сайдбар, окно чата, пузыри, поле ввода, диалог «новый чат»), только props, dev-витрина на моках.
- **State**: zustand-стор по контракту, хук поллинга с backoff и отменой, тесты с мок-клиентом.
- **DevOps & Docs**: ESLint + Prettier, GitHub Actions (lint/test/build), деплой на GitHub Pages, черновик README.

Ревью: каждая ветка сдаётся отдельно. Мерджить в `main` в порядке API → State → UI → DevOps.

### Фаза 2 — интеграция (роль 5)

- Сборка `App.tsx`: сессия, логин с проверкой `getStateInstance`, связка стор ↔ компоненты ↔ клиент.
- Оптимистичная отправка (`pending` → `sent`/`failed`), запуск и остановка поллинга, выход из аккаунта.
- Ручной e2e-прогон с реальным инстансом (ключи вводит тимлид в браузере, не в код).

### Фаза 3 — качество и сдача (роль 6 + тимлид)

- QA: чек-лист по критериям ТЗ, ревью кода, скриншоты/гиф, список багов.
- Исправления по отчёту QA (в той ветке/роли, к которой относится баг).
- Тимлид: деплой, финальный README, публичный GitHub-репозиторий, письмо на hr@green-api.com.

## Ритм работы для тимлида

1. Запусти роли 1–4 (кнопки задач в сессии Architect или вручную по `docs/tasks/*.md`).

## Риски

| Риск                                                 | Что делаем                                                                                          |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| CORS при запросах из браузера в GREEN-API            | API-роль проверяет на раннем этапе; запасной план: dev-proxy в Vite + serverless-прокси на хостинге |
| Разный формат `chatId` у Telegram/MAX/WhatsApp       | API-роль сверяет с документацией; `toChatId` в одном месте                                          |
| Поллинг дублирует сообщения или теряет их при ошибке | дедуп по `idMessage` в сторе; `deleteNotification` только после обработки                           |
| Утечка токена                                        | ключи только в `sessionStorage`/памяти, не в URL и не в репозитории                                 |
