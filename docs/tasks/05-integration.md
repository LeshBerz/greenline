# Роль 5: Integrator (фаза 2, запускать после мерджа ролей 1–4)

Сначала прочитай `CLAUDE.md`, `ROADMAP.md`, отчёты ролей (если тимлид их приложил) и публичные API:
`src/api`, `src/lib/phone.ts`, `src/store`, `src/hooks`, `src/components`.

**Ветка:** `feat/integration`
**Твои файлы:** `src/App.tsx`, `src/main.tsx`, `src/features/**`.

## Что сделать

1. `main.tsx` подключает `src/styles/global.css` и `tokens.css`.
2. `App.tsx`: нет credentials — показывается `LoginForm`, есть — основной экран.
3. Логин: создать клиент, вызвать `getStateInstance()`. `authorized` — сохранить credentials в сторе.
   Иначе показать понятную ошибку («инстанс не авторизован, привяжите аккаунт в консоли GREEN-API» / «неверные ключи»).
4. Клиент создаётся через `useMemo` от credentials. `useNotificationPolling(client, receiveIncoming)`.
5. Новый чат: `isValidPhone` → `openChat`. Невалидный номер — ошибка в `NewChatDialog`.
6. Отправка: `addOutgoing` → `client.sendMessage` → `resolveOutgoing`. При `failed` клик по статусу
   повторяет отправку (если UI это поддерживает; если нет, опиши в отчёте).
7. Выход: `logout`, поллинг останавливается.
8. Мобильная раскладка: переключение список ↔ чат.
9. Проверь `npm run build`, `npm test`, `npm run lint`. Проверь dev-сервер в браузере: без реального
   инстанса логин должен показать ошибку, а не упасть.
10. **Ручной e2e с реальным инстансом**: попроси тимлида ввести ключи в браузере. Ключи в чат,
    код и логи не вставлять. Пройди сценарий ТЗ целиком и зафиксируй результат в отчёте.

## Известная проблема: chatId в Telegram

`toChatId` строит `79001234567@c.us`. По заметке API-роли в `src/lib/phone.ts`, Telegram-инстанс
принимает такой id для отправки, но во входящих уведомлениях присылает **числовой id чата**. Из-за
этого ответ собеседника попадёт в новый отдельный чат, а не в тот, который пользователь создал по номеру.

1. Выясни по документации GREEN-API для Telegram (и по реальному инстансу на шаге e2e), как связать
   номер с числовым id. Варианты: поле `chatId` в ответе `sendMessage`; метод проверки аккаунта
   (например `checkAccount`/`checkWhatsapp` — найди аналог для Telegram); `senderData.chatId`
   исходящих уведомлений; сопоставление по `sender`/номеру в `senderData`.
2. Реализуй связывание так, чтобы ответ приходил в тот же чат. Если для этого нужно менять
   `src/store/**`, `src/api/**` или `src/types.ts`, в фазе 2 тебе это **разрешено**: другие роли
   закончили работу. Контракты меняй минимально, с тестами, и перечисли изменения в отчёте.
